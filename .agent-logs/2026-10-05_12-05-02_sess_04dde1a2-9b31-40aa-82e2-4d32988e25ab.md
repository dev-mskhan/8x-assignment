Both scripts are committed. Here's what was wrong and what's fixed:

**Root cause:** Kiro always sends `"prompt": ""` (empty string) in the `UserPromptSubmit` payload — the actual prompt text is only in the session transcript at `~/.kiro/sessions/.../messages.jsonl`. The old `capture-prompt.ps1` had no fallback for this, so it just wrote `[prompt text not available in hook payload]`.

**Fixes applied:**

1. **`capture-prompt.ps1`** — when the payload prompt is empty, it now reads the session transcript directly using the `session_id` from the payload. 2. **`capture-response.ps1`** — increased the retry loop from 5 × 400ms to 10 × 800ms (8 seconds total). The `Stop` event can fire before the transcript has finished flushing the assistant response, so the extra wait time gives it room to catch up.
